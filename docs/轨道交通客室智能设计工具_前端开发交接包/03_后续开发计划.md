# 后续开发计划

## 1. 开发目标

将当前静态 UI Demo 迁移为可维护的前端工程，先使用 Mock API 跑通全部业务流程，再逐步接入平台后端提供的 ComfyUI、AI Toolkit、DeepSeek 和其他任务接口。

## 2. 阶段一：需求冻结与接口定义

### 工作内容

- 确认页面清单、角色、权限、项目和资源组织方式。
- 确认首批 ComfyUI 工作流名称、输入字段和输出类型。
- 确认 LoRA 训练是否向普通用户开放。
- 确认 DeepSeek 助手的知识库、视觉能力和工具调用边界。
- 编写平台 OpenAPI 文档和统一错误码。

### 交付物

- 产品范围清单。
- 角色权限矩阵。
- OpenAPI 初稿。
- 工作流发布规范。
- 数据字典。

### 验收标准

- 前后端对每个页面调用哪个平台接口达成一致。
- 前端不需要了解节点编号、YAML 或模型服务密钥。

## 3. 阶段二：前端工程化与 Mock 联调

### 工作内容

- 建立 TypeScript、路由、状态管理、请求层和设计 Token。
- 拆分登录、工作台、生成、训练、资源、用户和助手模块。
- 建立通用上传、参数表单、画布、结果网格、任务卡和弹窗组件。
- 使用 Mock Service Worker 或等价方案模拟全部接口。
- 建立统一任务状态和 SSE Mock。

### 交付物

- 可运行的前端工程。
- 组件库和页面路由。
- Mock API 和示例数据。
- 基础单元测试、组件测试和端到端测试。

### 验收标准

- 不连接真实模型服务也能演示登录到结果保存的完整流程。
- 替换 Mock Service 后无需修改页面组件。

## 4. 阶段三：平台基础服务接入

### 工作内容

- 接入登录、退出、会话刷新和权限查询。
- 接入用户、角色和权限管理。
- 接入项目、资源上传、资源列表和共享权限。
- 接入统一任务查询、SSE 进度、取消和重试。
- 接入通知和审计记录。

### 验收标准

- 未登录不能进入业务页面。
- 普通用户无法访问管理员功能。
- 资源和任务按项目、用户正确隔离。

## 5. 阶段四：首个 ComfyUI 工作流闭环

### 工作内容

- 选择“客室效果生成”作为首个工作流。
- 建立工作流注册、Schema、参数映射和版本发布。
- 接入图片上传、工作流提交、实时进度、失败信息和结果保存。
- 验证遮罩输入、参考图、LoRA 和多结果输出。

### 验收标准

- 管理员发布工作流后，普通用户可在页面调用。
- 任务记录包含工作流版本、模型、参数和输出资源。
- ComfyUI 节点调整不要求修改前端代码。

## 6. 阶段五：扩展工作流与资源闭环

### 工作内容

- 接入 CMF、零部件、多角度和局部修改工作流。
- 接入资源库、版本对比、收藏、共享和报告引用。
- 接入 2D 生 3D 与报告生成适配器。
- 完善 GPU 队列、并发限制和服务状态。

### 验收标准

- 不同类型任务在前端使用同一套任务组件。
- 所有输出都可保存、检索并引用到其他模块。

## 7. 阶段六：LoRA 训练服务

### 工作内容

- 部署 AI Toolkit Worker 和训练适配服务。
- 接入数据集上传、图片与标注配对、参数校验和训练估算。
- 接入日志、进度、取消、断点续训和 checkpoint。
- 接入模型测试、下载、发布和 ComfyUI 模型同步。
- 建立 GPU 配额和存储配额。

### 验收标准

- 训练任务与前端会话解耦，关闭页面后任务继续执行。
- 发布后的 LoRA 可被已发布工作流引用。
- 普通用户无法提交任意 YAML、命令或服务器路径。

## 8. 阶段七：AI 多模态助手

### 工作内容

- 接入会话、消息、SSE 流式回复和历史记录。
- 接入 DeepSeek 文本推理和结构化输出。
- 接入视觉理解服务，对画布、图片、遮罩和报告做分析。
- 建立项目标准、材料规范和设计文化知识库。
- 为生成、检查和报告摘要提供受控工具调用。

### 验收标准

- 助手可以引用当前项目和选中资源。
- 回答包含引用来源，工具执行前需要用户确认。
- 更换 DeepSeek 模型不影响前端接口。

## 9. 阶段八：生产化

### 工作内容

- 完善安全、限流、审计、备份和密钥管理。
- 建立日志、指标、链路追踪和告警。
- 进行浏览器兼容、性能、无障碍和大文件上传测试。
- 进行任务并发、GPU 故障、服务重启和断点恢复测试。
- 建立开发、测试、预生产和生产环境。

### 验收标准

- 关键接口有超时、重试、降级和错误提示。
- 任务、资源和权限操作可追溯。
- 前端构建产物不包含任何模型服务密钥或内网地址。

## 10. 推荐优先级

### P0

- 登录和权限。
- 项目与资源上传。
- 统一任务协议。
- 首个 ComfyUI 工作流。
- 工作流注册、测试和发布。

### P1

- 其他生成工作流。
- 局部遮罩与屏幕捕捉。
- LoRA 数据集和训练。
- AI 文本助手。

### P2

- 多模态视觉助手。
- 2D 生 3D。
- 自动报告。
- 高级资源共享和版本比较。

## 11. 前端开发检查清单

- [ ] 页面组件不直接调用第三方服务。
- [ ] API Key 不进入浏览器。
- [ ] 所有上传文件转换为平台 `assetId`。
- [ ] 所有耗时操作转换为平台 `jobId`。
- [ ] 路由和按钮按权限控制。
- [ ] 工作流表单由 Schema 驱动。
- [ ] 错误信息包含可定位的 `requestId`。
- [ ] 任务支持取消、重试和刷新后恢复。
- [ ] 资源记录来源任务、模型和工作流版本。
- [ ] 核心流程具备端到端测试。

## 12. 仍需甲方确认

- 普通用户是否允许创建 LoRA 训练任务。
- 工作流发布是否需要审批和回滚。
- 资源按个人、项目、部门和共享库如何分级。
- 训练数据和生成结果的保存周期。
- DeepSeek 是否允许访问外网，或需部署兼容的内网模型。
- 多模态视觉模型的具体选型。
- 2D 生 3D 和报告服务是否纳入第一期。
- 屏幕捕捉是否允许采集其他应用窗口及其审计要求。
